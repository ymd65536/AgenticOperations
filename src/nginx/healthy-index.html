NGINX 404 の復旧を完了しました

● HTTP 200 - 正常状態

今回の状況

対象URL
http://20.106.237.102/health
症状
HTTP 404
復旧結果
HTTP 200

根本原因

原因: NGINX の location = /health が存在しないディレクトリを参照しており、健康チェック用のコンテンツが解決できませんでした。
つまり、VM や NGINX サービス自体が停止しているのではなく、ルーティング先のファイルシステム設定が破損していたため 404 になっていました。

この復旧の実際の手順

  1. 対象の URL に対して HTTP 404 を確認した
  2. NGINX のサービス状態とアクセスログ、エラーログを確認した
  3. 現在の設定ファイルを見て、/health のルート先が不正であることを特定した
  4. /var/www/html に対して正しいヘルスページを再設定した
  5. nginx -t で構成の妥当性を検証した
  6. nginx -s reload で設定を反映し、再度 URL を確認した
  7. 最終的に HTTP 200 へ回復した
